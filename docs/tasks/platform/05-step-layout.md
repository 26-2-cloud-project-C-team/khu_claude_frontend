# 05 단계형 화면 레이아웃

## 목표

검색 조건(US-01·02)과 공간 등록(AD-03)이 함께 쓰는 단계형 화면 틀을 만든다. 다른 화면도 쓰는 공통 여백·하단 CTA 영역을 같이 정한다.

## 할 일

- [x] 화면 공통 틀: 좌우 20, 제목 아래 24, 하단 CTA 영역(상단 16 + 세이프 에어리어 34)
- [x] 390 너비보다 넓은 화면(데스크톱 브라우저)에서 보여줄 방식 결정 후 반영
- [x] 단계형 틀: 뒤로가기 + 상단 진행 바(숫자 없음) + 질문형 H1 + Body 부제 + 내용 + 하단 Primary CTA 1개
- [x] CTA 비활성 상태 지원(필수값이 비면 오류 문구 없이 비활성)
- [x] 단계 전환 애니메이션: 좌→우 슬라이드(US-01 Check Point 1번)

## 완료 조건

- 진행 바 비율, CTA 활성·비활성에 대한 Widget Test가 있다
- 390×844 기준으로 US-01 A 시안과 여백이 맞는다

## 구현 메모

- 넓은 화면: `AppViewport`가 앱 전체를 최대 너비 480 열로 가운데에 둔다. `app.dart`의 `MaterialApp.router` builder에서 한 번만 감싸므로 화면마다 신경 쓰지 않는다
- 단계형 틀: `AppStepScaffold`. 진행 바는 현재 단계 번호가 아니라 채울 칸 수(`filledSteps`)를 받는다. US-00 목적 타일로 들어오면 목적 칸을 미리 채우기 때문이다
- 단계 전환: 검색 조건과 공간 등록은 각각 한 경로(`/search`, `/admin/spaces/new`) 안에서 단계를 바꾸므로, 라우터 전환이 아니라 `step`이 바뀔 때 내용만 슬라이드한다. 다음 단계는 오른쪽에서, 이전 단계는 왼쪽에서 들어온다
- 단계형이 아닌 화면도 `AppNavBar`(뒤로가기 줄), `AppCtaArea`(하단 CTA 영역)를 따로 가져다 쓴다
- CTA 비활성은 `onCta`를 null로 넘긴다. 오류 문구는 띄우지 않는다
